# Migration risk register

Derived from migration-plan section 12 on 2026-07-26. Likelihood is a Session 00 assessment; impact follows the plan's severity. Statuses are intentionally not marked resolved before their named evidence is obtained.

| ID | Risk | Owner | Likelihood | Impact | Mitigation | Trigger | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| R-01 | Service identity cannot use SQL, SMB, or managed-root ACLs. | Agent / deployment lead | High | Highest | Decide identity; prove SQL in Session 06 and SMB in Session 12 under that identity. | SQL login failure, SMB mapping failure, or access-denied managed-root operation. | Open — highest risk |
| R-02 | Cleanup causes catastrophic deletion. | Safety / Agent lead | Medium | Highest | Canonical managed-root policy, protected-root denylist, reparse rejection, preview, expiring challenge, typed confirmation, recomputation, audit, tests. | Any path-policy rejection failure or execute/preview mismatch. | Open — Session 11 |
| R-03 | Modern UI is not better than WinUI. | UI lead / product owner | Medium | High | Implement signal-path shell, accessibility and responsive gate; critique in Session 05; decide at Session 07 gate. | Poor keyboard/mobile/technician evaluation or parity failure. | Open — release gate |
| R-04 | Web API expands attack surface. | Agent security lead | Medium | High | Fixed loopback bind, same origin, local-admin auth, antiforgery, strict validation/CSP, listener test. | Non-loopback listener, unauthenticated mutation, permissive CORS, or secret/raw-path exposure. | Open — Sessions 01–03 |
| R-05 | Technician cannot choose an existing device file. | API / UI lead | Medium | High | Server-side allowlisted browse API with opaque handles, designed in Session 02. | A workflow needs a raw path input or cannot reach an approved artifact. | Open — Session 02 |
| R-06 | Legacy secrets cannot be recovered under service identity. | Configuration lead | Certain | Medium | Accepted: import non-secrets only and prompt once for both passwords. | Legacy secret decryption attempted by service. | Accepted decision — Session 03 implementation pending |
| R-07 | Agent restart interrupts long SQL/file work. | Agent lead | Medium | Medium | Accept parity-or-better in-memory job lifetime; locks; explicit UI warning that restart clears in-flight jobs. | Agent restart during operation. | Accepted risk — Session 04 implementation pending |
| R-08 | Browser disconnect causes a duplicate command. | Agent / UI lead | Medium | Medium | Agent owns jobs; UI rehydrates read-only by operation ID and never replays a mutation. | SSE/network drop followed by reconnect. | Open — Session 04 |
| R-09 | Cut features return through scope creep. | Migration lead | Medium | Medium | Treat plan section 0.3 as decision authority; require ADR/plan change with owner. | Proposed SQLite, SignalR, PWA, LAN mode, pairing, roles, or durable client store. | Open — continuous |
| R-10 | Angular/.NET dependencies cannot restore at a branch. | Build / release lead | Low | Low | Pin lockfiles centrally; ship self-contained runtime; branch device requires neither Node nor NuGet. | Branch deployment attempts online restore or a lockfile mismatch. | Open — Session 01 / 14 |
| R-11 | WinUI is removed before parity is proven. | Migration lead / product owner | Low | Low | Strangler sequence, parity matrix, publish-and-run baseline, Session 14 explicit approval and dedicated removal commit. | Proposed removal before every parity row/release gate passes. | Open — Session 14 boundary |
